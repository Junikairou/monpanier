# Règles de collaboration — projet Mijoté

Consignes du propriétaire du projet (non technique). À respecter par tout agent qui travaille sur ce dépôt.

## Impératif

- **Toujours utiliser AskUserQuestion** dès le moindre doute, même minime, même si tu penses avoir compris — quitte à poser beaucoup de questions. Mieux vaut demander que faire une correction après coup.
- **Minimiser la consommation de tokens.** Éviter les explications superflues, les relectures inutiles, le travail non demandé.
- **Être concis, clair, compréhensible et efficace** dans les réponses. Pas de jargon technique inutile — l'utilisateur n'est pas développeur.
- **Une modification du site/de l'app impacte tous les comptes**, sauf preuve explicite du contraire (ex. une donnée déjà scopée par utilisateur).
- **Toujours pousser sur GitHub** après une modification, sauf preuve explicite du contraire (ex. utilisateur dit explicitement de ne pas le faire).
- **En cas d'incohérence** (demande contradictoire, information manquante, doute sur l'impact), le signaler via AskUserQuestion plutôt que de deviner.

## Contexte projet

- App de planning de repas ("Mijoté") — Expo (React Native + web), pensée pour devenir une app mobile native plus tard.
- Backend : Supabase (auth + base de données), projet `kjltmojlewrnwimzskgj`.
- L'utilisateur n'est pas à l'aise avec le code : éviter le jargon, expliquer les actions en langage simple, guider pas à pas pour toute étape qu'il doit faire lui-même (comptes externes, clés API, etc.).
